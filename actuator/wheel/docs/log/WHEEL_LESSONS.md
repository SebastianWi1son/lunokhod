## 二、收获清单（沉淀为方法论）

### 1. 状态写回铁律（#1 的升华）
有状态组件（Ramp/LPF/积分/滤波）统一范式：**先算 out → 写回状态 → 最后 return**。任何提前 return 都可能漏写状态。

### 2. "0 = disabled" 惯例（#5 的升华）
可选功能用 0 当开关：`max_rate=0` 关斜坡、`thresh<=0` 关积分分离。**不用 bool 开关**（避免双机制），0 语义写进 Config 注释。

### 3. Config 聚合 + 组件边界（#10 关联）
- 参数聚合成 Config struct，**粒度 = 组件边界**：SmoothPlanner 的配置进 `SmoothPlannerConfig`，PID 的进 `PIDConfig`，Wheel 组合它们就传两个 config
- 通用层（PIDConfig）默认 0 中立；具体数值（轮速环 3600/1200...）是应用层知识，放调用处/preset，**不进通用头文件**

### 4. 函数指针回调 + motor_id 参数通道
函数指针**无法捕获状态** → "哪个电机"只能走参数通道。真机回调（电机库全局函数）无捕获需求，函数指针零开销够用。升级触发器：需要捕获且编译期已知→模板；运行时才定→std::function；对象层次→虚接口。

### 5. 单位无关接口 + 文档承担语义
算法层是纯数值运算（不关心 1.0 是 rpm 还是 rad/s）→ 命名中性（`MeasureSpeedFn`/`target_speed_`），单位由调用方约定，文档声明，**锚点测试钉单位**。命名用 measure（采样+换算）而非 get/read（读缓存）。

### 6. dt 是实测值，不是配置值
M 法测速公式 `rpm = Δ脉冲/PPR × (1/dt) × 60` 数学上必需 dt；中断延迟/任务抖动让实际间隔≠配置值 → **dt 穿透回调**，由 Wheel 作时间基准提供者。

### 7. 测试方法论
- **锚点测行为不测数值**：期望值先手算（LPF 0.3333/0.5556/0.7037、Ramp 34 帧、积分 0.05/0.15/0.25），close() 容差
- 每个 Config 显式配齐 limit（默认 0 会悄悄钳死输出——测试里踩了两次）
- 空回调保护、reset 后重爬，都是行为锚点

### 8. 参数调校方法论（#10 的升华）
模型增益与参数不匹配时，先理解"每个参数在干嘛"（积分分离挡积分→纯 P 静差），再**写扫参脚本**找可行组合，最后在 example 里用调好的参数演示（example 是演示，参数自调合法，注释写明不是 legacy 出厂值）。

### 9. 发布流程实战（SemVer + 渐进稳定分支）
main 全绿 → commit → release/v0.1 → VERSION+CHANGELOG → tag → CLion push（命令行 GitHub 认证在 WSL 环境不可用，CLion OAuth 绕行）→ 回 main。tag 未推送前可修正（CHANGELOD→CHANGELOG），推送后不可变。

## 四、v0.1.1 之后：命名空间 + effort 暴露（2026-09-17）

### 1. "全局名"是债，而且**越早还越便宜**
`PID` / `PIDConfig` / `LPF` / `Ramp` / `SmoothPlanner` 一直躺在全局命名空间（15 个名字），
谁 include 谁被注入。**迁到上游 ctlkit 之后才看清**：定义已经不在本仓，
收口只需改 4 个转发头（`using` 收进 `namespace wheel`）—— 若等到"下游接了三个项目"再改，
就是三倍调用点。**教训：破坏性改动要在消费者最少的时候做，而不是"不急"的时候做。**

### 2. 转发头的注释也是文档，会过期
4 个转发头里白纸黑字写着"保留**全局名**…调用点零改动" —— P29 做完整整相反的事。
**改代码时必须把同一文件里的解释性注释一起改**，否则下一个 agent 会照注释办事。

### 3. `effort` 要用**外部观察者**做金标
新增 `Wheel::effort()` 的测试不是"读出来看看"，而是拿**假 HAL 回调实际收到的那个值**比对
（`loop.wheel_effort(i) == last_pwm(i)`，未用到的轮 = 0）。这样"记错值 / 索引错 / 不记录"三种错法都能变红。
**教训：暴露出来的量，金标要来自它的下游（谁真的收到了），不是它的内部。**

### 4. 显式 `cast` 是"零行为变化"的证明
P23 那条隐式 `float→int16_t` 改成 `static_cast` 后，KND 仿真输出**逐位不变** ——
顺带证明了当初的隐式转换就是纯截断（没有任何意外的舍入分支）。
**教训：把"隐式"写成"显式"不只是消告警，它还能把"我以为它在做截断"变成"我知道它在做截断"。**

### 5. 接口卫生是**政策**，不是组件级小事（P29 → P32）
P29 只给本组件加了命名空间，其它组件还在全局 —— 结果是最不一致的状态（"一半 `wheel::`、一半全局"）。
用户一句"namespace 不是类似 foucault 那样整个项目一个根吗"点破了它。
**教训：动手前先问"这是这一层的事，还是全仓的事"。** 根命名空间的价值正是**防撞名**，
所以它必须**全仓一次做完**（`lunokhod::` 根 + `lunokhod::<组件>`）；半个命名空间等于没有政策。
