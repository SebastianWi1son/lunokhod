## 0. 一句话架构

**两条链 + 一个汇合点**：下行命令链（限幅 → 逆运动学 → 轮速）+ 上行感知链（状态估计 → 误差修正），
两条链在 `(Vx, Vy, ω)` 三量层面汇合，汇合后走"先限幅、后分解"的唯一通道。
底盘差异只存在于下行链的逆运动学一步；传感器差异只存在于上行链的估计一步。

## 1. 链路总图

```
┌─ 应用层（不属于控制器）───────────────────────────────┐
│ 规划/遥控/任务：产生期望运动 cmd = (Vx, Vy, ω)          │
└──────────────────────┬─────────────────────────────┘
                       │ ① 下行：期望命令
                       ▼
┌───────────────────────────────────────────────────────┐
│ 控制器 ── 命令通道（下行）                               │
│ 1. SpeedLimiter     (Vx,Vy,ω) → 限幅后 (Vx,Vy,ω)      │
│                    速度/加速度/Jerk 三级，三量分别限      │
│ 2. Inverse Kinematics → [ω₁..ωₙ] 各轮目标角速度        │
│                    底盘差异唯一消化点（差速/Mecanum/全向）│
└──────────────────────┬───────────────────────────────┘
                       │ [ω₁..ωₙ]
                       ▼
┌───────────────────────────────────────────────────────┐
│ 驱动层（不属于控制器）：Wheel PID → 电机驱动 → 电机        │
└──────────────────────┬───────────────────────────────┘
                       │ 实际运动（物理世界）
                       ▼
               ┌───────────────────────┐
               │ 底盘在运动：位置/速度/姿态 │
               └───────────────────────┘
                       │
                       ▼
┌─ 传感器层：灰度阵列 / IMU / 编码器 / 电磁 ─────────────────┐
│ 各自原始读数 z₁..zₙ（不同坐标系、不同噪声特性）              │
└──────────────────────┬───────────────────────────────┘
                       │ ② 上行：原始测量
                       ▼
┌───────────────────────────────────────────────────────┐
│ 控制器 ── 感知通道（上行）                               │
│ A. 残差监测（consistency / FDI）                        │
│    两个独立来源对一下 → 残差 → 权重。**不是融合**。        │
│ B. 状态估计（sensor fusion）                            │
│    多传感器 → 带语义的状态估计：横向偏移 e_y、航向误差 e_θ │
│    （或实际三量估计）。本质不通用：按传感器拓扑提供模板。     │
│ C. 误差 → 修正                                          │
│    状态误差 → δcmd = (δvx, δvy, δω)                    │
│    口述里的"语义化预期改变量"在这里落地。                  │
└──────────────────────┬───────────────────────────────┘
                       │ ③ δcmd（修正）
                       ▼
              汇合点：cmd_total = cmd_desired + Σδcmd
              （在限幅器之前，见 §4）
```

两条链的运行频率可以不同（下行 1kHz；上行 100Hz~1kHz，估计/修正各层独立 tick）。

## 2. 下行链（命令 → 轮速）— lunokhod 已设计

| 模块 | 输入 | 输出 | 职责 | 状态 |
|---|---|---|---|---|
| Command Interface | 应用层 | cmd | 统一 `(Vx,Vy,ω)` 接口，底盘无关 | 已设计 |
| SpeedLimiter | cmd | 限幅 cmd | 三量分别限速度/加速度/Jerk | 已设计 |
| Inverse Kinematics | 限幅 cmd | 轮速 | 差速/Mecanum/全向 N 轮；**先限幅后分解** | 已设计 |
| Odometry（可选） | 轮速 | (x,y,θ) | 正运动学 + 积分 | 已设计 |

**为什么先限幅后分解**（THEORY §3.3 的既有结论）：先分解再限幅会让底盘运动扭曲
（限幅器约束的是车体三量，不是单轮）。这条原则决定了汇合点必须在三量层面（§4）。

## 3. 上行链（传感器 → 修正）— 本设计重点，也是口述里最模糊的部分

### 3.0 先纠一个概念：这不是「一个融合层」，是三件不同的事

> **2026-09-15 补**：原来这里只有两层（状态估计 / 修正）。核对 `reference/robot_localization`
> （ROS 生态主流融合库）后发现**漏了最前面一层 —— 残差监测**。
> 三层的区别不是「细度」，是**输出的性质不同**：

| 层 | 干什么 | 输出 | 叫法 |
|---|---|---|---|
| **A. 残差监测** | 两个**独立来源**对一下，发现不一致 | **残差 / 权重** | monitor · FDI · consistency check |
| **B. 状态估计** | 多源**合成**更好的估计 | 估计量 | fuse · sensor fusion |
| **C. 误差修正** | 状态误差 → 命令修正 | `δcmd` | control |

**A 不是融合。**「不可信怎么办」永远是**使用者**的决定，所以 A 只该**报告**，
不该替谁下判断 —— 库的职责到此为止。

**而且行业里 A 甚至不是一个模块**：`robot_localization` 把它做成**每个量测的门限参数**
（`filter_base.cpp` 的 `checkMahalanobisThreshold` + `ros_filter.cpp` 里那一堆
`*_rejection_threshold`），超限即**整条量测丢弃**（`ekf.cpp` 里没有 else 分支）。

### 3.1 层 A：残差监测（FDI）

- **职责**：把两个来自**不同链**的**同类量**对一下。首选是**瞬时量**，不是位姿：
  ```
  wz 残差 = FK(measured_wheel_speeds).wz  −  gyro_z
  ```
  两侧都是瞬时量 → **谁都不用推算对方、谁都不用积分**。
- **为什么不用位姿 / 角度比**：积分是低通，会把要抓的短时残差**抹平**；
  陀螺零偏还会积成漂移，**制造假残差**。
- **为什么不用 IMU 测位移**：双重积分不可用。位移比较**必须有外部绝对参照**
  （视觉 / 激光 / GNSS）—— 那是另一个层次。
- **输出**：残差 →（门限）→ **权重**。**不是 `is_slipping` 旗标** ——
  旗标只能报警，权重才能被下游**使用**。
- **归属**：库里只到「**暴露可观测量**」为止（装配层的只读口 + `odometry` 的 `SampleSink`）。
  **残差生成器与门限在库外**（它们要库外的标量；跨库只传标量）。
- **被什么卡住**：阈值要「正常 / 打滑」的**标注数据**，现在没有 → 见 `TODO.md` P19。
- **前提**：`L0`（`cmd` vs `twist`，只用编码器）**检测不到整车打滑** ——
  轮子打滑时编码器跟着转。它实际检的是**执行器故障 / 轮间一致性**。

### 3.2 层 B：状态估计（sensor fusion，术语已确认）

- **职责**：把多个传感器的原始读数（不同坐标系、不同噪声）合成**带语义的状态**：
  车相对参考线/目标的横向偏移 `e_y` 与航向误差 `e_θ`（或车身实际 vx/vy/ω）。
- **本质不通用**（用户确认 + lunokhod 结论）：每个估计方案依赖具体传感器拓扑。
  产品策略 = 按拓扑提供模板，不追求统一抽象。lunokhod 已有一个模板：
  前后双横向传感器 + IMU（gyro_z）：
  ```
  横向偏移 = (e_front + e_back) / 2
  航向误差 = (e_front - e_back) / L        ← 纯几何
  融合航向 = α·(积分航向 + gyro_z·dt) + (1-α)·几何航向   ← 互补滤波
  ```
- **单传感器退化**：只有一个灰度阵列时，"估计"退化为直接读数（读数本身就是误差），
  估计环节消失——这正是口述里"误差直接加权进控制"的直觉来源。

### 3.3 层 C：误差 → 修正

- **职责**：状态误差 → 对三量的修正 `δcmd = (δvx, δvy, δω)`。这是口述"对某一参考点的
  横向/纵向预期改变量"的正式落点：**参考点统一为车体中心**，修正量作用在三量上。
- 简单实现：对角 P/PD（如 δω = K_θ·e_θ + K_y·e_y）；前瞻/模型预测为进阶。
- 与 lunokhod 的关系：kinematics 刻意排除 PID，**这一层在两个设计里都是空白**，需要新设计。

### 3.4 概念澄清：三个"加权"不是一回事

口述里"加权"出现了两次，加上本层新识别的门限，共是**三个不同层的旋钮**，别混：

| | 出现在哪 | 含义 | 例子 |
|---|---|---|---|
| **门限阈值 N** | **层 A** | 残差多大算「不对劲」 | 马氏距离的 N-sigma |
| 融合加权 α | 层 B 内部 | 数据源之间的信任度分配 | 互补滤波 α=0.95~0.98 |
| 修正增益 K | 层 C | 误差 → 命令的响应强度 | 循线的 Kp |

α 回答"该信谁"，K 回答"反应多猛"。调参时改的是不同旋钮。

## 4. 汇合点（关键设计决策）

```
cmd_total = cmd_desired + Σδcmd      （Σδcmd = 各修正源之和，仲裁见 §7-Q4）
cmd_total → SpeedLimiter → IK → 轮速
```

- **位置**：三量层面、限幅器之前。
- **理由**：① 限幅器对整体命令统一约束（先限幅后分解原则）；② 修正与期望同等对待，
  不绕过限幅（否则一个传感器故障能直接拉爆轮速）；③ 底盘无关——差速车收到 δvy 自动忽略。
- **被否决的替代**：轮速层面汇合（扭曲运动）；修正绕过限幅器直接进 IK（危险）。

## 6. 对 AI agent 友好的落点（口述新增设计目标）

## 8. 与口述三层心智模型的对照

- 口述猜"3~4 层" → 实际是 **5 模块、2 条链、1 个汇合点**（应用层/驱动层不计入）。
- 口述猜对的部分：三量统一接口、底盘差异消化在底层、sensor fusion 在上层。
- 口述需修正的部分：
  1. "误差加权给控制器"应拆成两个环节——先**估计**（融合，α），后**修正**（K）；
  2. 修正量的汇合点不在差速控制层面（口述里"加减到差速"），而在三量层面、限幅器之前
     ——差速只是被修正的三量之一碰巧实现为 speed/steer 加减；
  3. "对所有传感器抽象成统一偏移量"在层 B 做不到（本质不通用，按拓扑模板化），
     **层 C 才是统一抽象的真正落点**（所有修正源输出同构的 δcmd）；
     而**层 A 反而天然通用** —— 它只输出残差 / 权重，与传感器拓扑无关（见 `TODO.md` P19）。
